# 吉利 FX11 氛围灯接入（产品侧）

> 2026-10-15。车机 `geely_fx11` / `CS11_A4`（`Build.DEVICE=msmnile_gvmq`）。
> 底层实测见 [`headunit/15-氛围灯与HUD控制实测.md`](headunit/15-氛围灯与HUD控制实测.md)，
> 控制者/协议盘点见 [`headunit/10-氛围灯与灯光.md`](headunit/10-氛围灯与灯光.md)。
> BYD 那套的说明见 [`../docs/BYD_AMBIENT_LIGHTING.md`](../docs/BYD_AMBIENT_LIGHTING.md)。

## 一、为什么要加门控

DiPlay 原有的氛围灯（随音乐律动 / 跟随封面 / 常亮）**只认识 BYD 的灯通道**：走 ADB + 独立
`app_process` worker 进程，通过 BYD 网关服务读写，模型是 **色号 1..31 / 亮度 1..6 / 区域 front·rear·all**。
本车没有这条路，于是设置里的"只读检查"必然失败，开关根本存不下去。

本车的灯是 **ECARX 车 API**（`ecarx.car.jar` 在 boot classpath）：

```
ECarXCar.createCar(ctx, conn).connect()
  .getCarManager("car_publicattribute")        // = ECarXCarSetManager
      .getECarXCarAmbliManager()               // = ecarx.car.hardware.vehicle.ECarXCarAmbliManager
```

普通第三方 uid（10059）、**不需要 ADB、不需要 root、不需要 worker 进程**。

## 二、两套模型的差异与映射

| 维度 | BYD | 本车（ECARX） | 映射做法 |
| --- | --- | --- | --- |
| 颜色 | 色号 **1..31** | **任意 24bit RGB** | 复用 UI 已显示的色板 `AmbientAlbumPalette.previewRgb(1..31)`（丢掉 alpha） |
| 亮度 | raw **1..6** | **0..255** | **显式表** `25/60/100/150/200/255`。两套刻度无关（BYD 的 1 档在汉上可能是全灭），不按比例换算 |
| 区域 | front/rear/all (**1..3**) | **Zone1..5 + ZoneAll** | **只写 ZoneAll**。本车没有已知的 front/rear→zone 映射，猜错会点亮错误位置；`area` 参数照收但不参与写入 |
| 通道 | ADB + worker 进程 | 同进程反射 | 两套传输共用一个 `AmbientLampSession`（串行生命周期、快照还原、退避重试、不透明确认） |

## 三、代码结构

| 文件 | 职责 |
| --- | --- |
| `shared/.../hud/EcarxAmbientLightPolicy.kt` | 纯逻辑：映射表、快照校验、还原顺序、`PATypes.dataValue` 解析。无反射，可单测 |
| `shared/.../hud/EcarxAmbientLight.kt` | 反射传输：连接、快照读、`CB_Zone*` 写、还原。连接在**主线程**建立（厂商类要用注册线程的 looper 收回调），读写跑自己的单线程 executor |
| `shared/.../media/AmbientLampSession.kt` | 泛型化：快照类型参数化 + 注入 `validate` + `leaseMillis`，两套车共用同一份生命周期 |
| `shared/.../media/AmbientMusicController.kt` | 按设备门控选 session（启用哪条才会打开客户端）；`checkSupport` 分流——本车**直接读属性**，不要 ADB |

**门控**：`EcarxAmbientLightPolicy.supported()` 要求 `Build.DEVICE == "msmnile_gvmq"`，
与探针里所有"会动车"的操作同一个门。**别的车绝不会被写灯**，BYD 行为完全不变。

写入方法：`CB_ZoneAllStatusSettings(1)` → `CB_ZoneAllColorSettings(rgb)` → `CB_ZoneAllIntensitySettings(0..255)`。
还原顺序照抄探针：先 ZoneAll，再 Zone1..5，每个区先 Status 再 Color 再 Intensity（避免本来关着的区被闪一下）。

## 四、本车音频的现实

本车**当前**把 CarPlay 音频交给车机自己的蓝牙播放器，DiPlay 侧没有任何音频 track，因此音频包络没有输入，
"随音乐律动"这类模式不会动（**常亮所选颜色**仍然生效，退出按快照还原）。

但这不是终点：打开 **Settings → Display and performance → Buffered music (experimental)**
（会重连 CarPlay）后，Apple Music 的 AAC-LC 帧会**走 TCP 交给 DiPlay 自己的渲染器**
（见 [`../docs/BUFFERED_AUDIO.md`](../docs/BUFFERED_AUDIO.md)），那时包络就有数据，
**音频律动无需改代码即可生效**。因此产品侧**保留了全部模式**，没有做设备删减。

## 五、实测读数（2026-10-15，本车现场）

探针 `--ez amb_li true`（只读，同一条反射路径）读到的属性类型：

```text
ECarXCar.connect() -> isConnected()=true                      # 实测约 4.0 s 才连上（冷启动可能更久）
getPA_Zone1ColorSettings()       dataValue = 16736077          # 数字
getPA_Zone1IntensitySettings()   dataValue = 20                # 数字
getPA_Zone1StatusSettings()      dataValue = Off               # ★ 枚举 On/Off，不是数字
getPA_Zone2ColorSettings()       dataValue = 9140479
getPA_Zone3..5ColorSettings()    dataValue = 0                 # 3~5 区未用
getPA_ZoneAllColorSettings()     dataValue = 16751663
getPA_ZoneAllIntensitySettings() dataValue = 20
getPA_ZoneAllStatusSettings()    dataValue = On                # ★ 同上
getPA_AmbLiModSetting()          dataValue = CustomizedMode    # 本车当前就是自定义模式，会采纳 zone 写入
```

**坑（已踩并修）**：`status` 是 `On`/`Off`。若按数字解析，`Off` 会解析失败 →
快照被判为"不可读" → `begin` 抛错 → 功能永远起不来。所以 `parseDataValue`（数字）与
`parseStatus`（`On`→1 / `Off`→0，也接受数字形式）必须分开；**不可读的状态绝不能被当成 0**，
否则还原时会把亮着的区写成"关"。

> 注意：探针 `AmbientApi.dataValueInt()` 在读 `Off` 时返回 0、读 `On` 时**也返回 0**，
> 所以探针的 zone 还原实际会把原本 `On` 的区写回 `Off`。产品侧没有沿用这个行为。

另外确认：`getPA_VF_HUD_*` 的读数里 `getPA_HUD_DispModSet()` 依旧抛
`ClassCastException: Integer cannot be cast to byte[]`（厂商 bug，与氛围灯无关）。

## 六、待上车确认

1. 设置 → Advanced → 氛围灯，**只读检查应通过**（以前必然失败）；
2. 选色 + 亮度后灯带**真的变色**、档位与亮度对应；
3. 关掉开关后**灯回到原值**（快照还原），日志里 `lamp snapshot all=... zones=...` 应等于动手前的车灯状态；
4. 若灯**不跟着变**，大概率是车机当前氛围灯模式（`getPA_AmbLiModSetting`：`CustomizedMode` / `ThemeMode` / `DriveMode` …）
   不采纳自定义 zone 写入。日志里的 `lamp readback ... mode=` 就是判据；
   届时在 `begin` 里加一次 `CB_AmbLiModSetting(CustomizedMode)` 并把它纳入快照还原即可。
